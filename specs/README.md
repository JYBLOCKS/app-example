# Specifications

Specifications define intended behavior before implementation. They are the primary reference for acceptance criteria, boundaries, interfaces, and non-functional requirements.

## Organization

- `product/`: user problems, workflows, scope, and product acceptance criteria.
- `frontend/`: frontend architecture, feature behavior, UI states, accessibility, and client integration contracts.
- `backend/`: domain behavior, API contracts, persistence, authorization, and failure handling.
- `infrastructure/`: environments, delivery, runtime, security, observability, and recovery.

## Status values

Use one of: `Draft`, `In Review`, `Approved`, `Superseded`, `Rejected`.

Only approved specifications authorize implementation unless a task explicitly requests discovery or prototyping.
