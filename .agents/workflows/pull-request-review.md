# Workflow: Review a Pull Request

1. Read the linked requirement, task plan, and decisions.
2. Inspect the diff by risk area rather than file order.
3. Verify acceptance criteria and test evidence.
4. Run or inspect relevant quality gates.
5. Check architecture, security, accessibility, performance, and failure behavior.
6. Report prioritized findings with evidence.
7. Approve only when blocking risk is resolved or explicitly accepted.
