# Harness: Feature Readiness

- [ ] The feature is in approved product scope.
- [ ] A primary actor and happy path are defined.
- [ ] Acceptance criteria are observable.
- [ ] API/data contracts exist when needed.
- [ ] Authorization rules are explicit.
- [ ] Loading, empty, success, validation, and failure states are defined.
- [ ] Accessibility and performance requirements are stated.
- [ ] Test levels are mapped to criteria.
- [ ] Dependencies and rollout risks are understood.

Result: Ready / Not ready
